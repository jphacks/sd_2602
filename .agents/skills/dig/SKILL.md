# Dig：深掘りと意思決定の記録

計画・設計について対話し、ユーザー自身の判断を洗練する。深掘りの終了後、まとめを会話に出力してからADRと用語集をMarkdownファイルに保存する。このスキル自体が深掘りを担当し、別のdigスキルや専用のSkillツールは要求しない。

## 対話

- 作業場所のAGENTS.mdと、指定されている自己コンテキストを参照する。会話ですでに分かっている内容を聞き直さない。
- 対象が不明なら、深掘りしたい計画・設計を一つ尋ねる。対象が分かっていれば、判断に最も影響する不明点から始める。
- 一度に一〜三問を目安に、回答を待って次の質問を選ぶ。一括の長い質問票にしない。
- 目的、成功条件、現状の問題、対象者、範囲と範囲外、制約、前提、代替案、トレードオフ、失敗時の影響、検証方法を必要に応じて掘る。すべての項目を機械的に質問しない。
- 抽象的な回答には具体例や反例を求める。矛盾は責めずに示し、どちらを優先したいか確かめる。現状維持も選択肢として扱う。
- 事実、ユーザーの希望、仮説、AIの提案を区別する。提案や沈黙をユーザーの決定として扱わない。
- 関係する価値観や懸念を確認するが、技術的な設計から無関係な個人の心理へ話題を広げない。自己理解を求められている場合は、前提・感情・価値観・恐れを分ける。
- 重要な判断が見えてきたら理解を短く返し、残る論点に絞る。結論や実装を先回りしない。

## 終了とまとめ

ユーザーが「まとめて」「終了」などと伝えたら、未回答があっても質問を止めて整理する。目的・主要な選択肢・判断理由が十分に明確になった場合もまとめに移れる。未決事項を埋め合わせて確定扱いしない。

まず会話に次の形式でまとめを出す。内容がない項目は「未決」「該当なし」と明記する。

1. テーマと目的
2. 背景・現状の問題
3. 明らかになった前提・制約・価値観
4. 検討した選択肢と比較
5. 決定事項と理由（提案・未決を区別）
6. 期待する効果・不利益・リスク
7. 未決事項と検証方法
8. 次の一歩
9. 用語と、この会話での意味

## Markdownへの記録

まとめの出力後、作業場所の保存規約を確認して記録する。規約がなければ現在のプロジェクトのdocs/adr/を使う。作業場所が不明な場合だけ保存先を尋ねる。

- ADRは既存の採番・命名に合わせる。規約がなければYYYY-MM-DD-短いテーマ.mdとし、同名が存在する場合は別名を選ぶ。無関係な記録を上書きしない。
- 一つの主要な意思決定につき一つのADRを基本とする。密接な判断は一つにまとめる。
- 以下の形式を使い、会話の内容を要約する。逐語録や不要な個人情報は含めない。

```markdown
# ADR: タイトル

- 日付: YYYY-MM-DD
- 状態: 提案 / 決定 / 保留

## 背景と目的
## 判断基準・前提・制約
## 検討した選択肢
## 決定内容と理由
## 影響（利点・不利益・リスク）
## 未決事項・検証方法
## 次のアクション
## 関連用語
```

- 状態を「決定」にするのはユーザーが選択を表明した場合だけ。未決の場合は「提案」または「保留」とし、決めていない点を記録する。
- 用語集は既存のものがあればそこへ追記し、なければ同じフォルダにglossary.mdを作る。「用語 / この文脈での定義 / 関連ADR」の表にする。既存の異なる定義を黙って置き換えず、文脈ごとに分ける。用語がなければその旨を記録し、架空の項目を作らない。
- 保存後にファイルを読み直し、会話にない決定の追加や未決事項の欠落がないか確認する。ADRと用語集への絶対パスのリンクを返す。
- 書き込みに失敗したら保存済みと報告せず、理由と保存予定のMarkdownを示す。
