# 再開手順・検証計画

更新：2026-10-17。現時点の優先はManagerでの「テスト」用カード作成。アプリ本体の実装を勝手に進めない。

## 1. 操作環境を確認
- 利用者によるCodex再起動後、画面の一覧・読取りだけを試す。
- 失敗すれば同じ呼出しを繰り返さず、別方式を選ぶ。TinyFish接続または独立Playwright案は未着手。
- ログインが必要なら利用者が行う。認証情報をコンテキストやリポジトリへ保存しない。

## 2. 作成だけを検証
- SD_2602アカウントと、既存「日程テスト」／キーワード「テスト」の有無を確認。
- [指定値](manager-cards.md)でプロダクトカードを作成。保存後に読み直し、画像・タグOFF・価格OFF・改行を確認。
- キーワード応答「テスト」に割り当てる。Managerの応答機能が有効か確認し、不要な一律応答との競合を確認。
- 利用者が個別トークで「テスト」を送り、カードとボタンからのテキスト投稿を確認する。作成依頼を、勝手なテストメッセージ送信の許可に拡大しない。
- 完了条件：アイテム・応答設定の存在と値を管理画面で確認し、実LINEでの表示確認を別に記録。

## 3. 削除・再登録を検証
- 作成成功後に、検証対象だけを特定して旧応答削除→同じキーワードで再登録を試す。
- 管理対象の識別名・旧設定の復元材料・途中失敗時の停止条件を先に決める。
- 共有中の設定や無関係なカードを削除しない。実行時の操作ツールに必要な確認手順を守る。
- 新応答の確認後に、不要になった旧カードを削除する。
- 完了条件：キーワード再利用、重複応答なし、削除対象の正しさ、失敗時の復旧を確認。

## 4. サーバー化の判断
ローカルで一周成功してから検討する。
- ブラウザー再起動後の認証再利用、ログイン期限切れ時の人への引継ぎ。
- 新カード作成・旧応答削除・再登録の各段階を記録し、二重作成・途中失敗を判定できること。
- 設定更新中の短い応答停止を許容するか、管理対象をどう命名するかを確定。
- Base44との役割分担とサーバー環境は未決。無人運用可能とはまだ断言しない。

## 引継ぎ時の注意
- 現行コードは最小text Bot。以前の18テスト・カルーセル実装は過去の版。最新は4テスト成功の記録。
- 本体DB・外部設計は[既存の設計入口](../schedule-design-index.md)を読む。本会話のManager自動化で置き換えない。
- 既存リポジトリには他作業の未コミット変更がある。Git reset・一括コミット・pushをしない。
- 作成／削除・実機確認・接続復旧の結果は、実施の証拠がある段階だけ完了扱いにする。
