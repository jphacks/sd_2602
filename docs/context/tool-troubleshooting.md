# 画面操作エラーと代替手段

更新：2026-10-17。原因は未確定。仮説を修復済み・確定原因として扱わない。

## 確認済み
ブラウザー操作の初回接続、Windows操作用Node REPLの初期化の双方が次で失敗した。

```text
failed to write kernel assets:
指定されたパスが見つかりません。 (os error 3)
```

- LINEの管理画面へ到達する前の実行環境準備で発生。
- ブラウザー操作セッションをリセット後、再試行しても同じエラー。
- Node.js本体・確認したTEMP/TMP・Codexランタイム・この会話の出力フォルダーは存在した。通常のファイル操作やNodeのテスト実行は可能。
- ログDBを読み取り専用で調査。確認できたスナップショットに対象のERROR/WARNは見つからず、欠落パスを特定できていない。最新ログ全体を確認できたとは言わない。
- LINE認証・通信障害とする根拠はない。
- 設定変更、権限緩和、再インストール、Codexの再起動は実施していない。

## 仮説
有力候補は画面操作用ランタイムの作業パス・配布資材・セッション状態の不整合。
os error 3だけで、どのフォルダーが欠落しているか、移動・更新・権限のどれが原因かは断定できない。

## 復旧・代替
1. 他の作業を保存し、利用者がCodexを完全終了・再起動。その後、画面の読取りだけ再試験する。成功保証はない。
2. 別系統のクラウドブラウザー「TinyFish」を候補として発見。未導入・未接続。接続後もLINEログイン・画像アップロード・作成削除の検証が必要。パスワードをチャットへ貼らない。
3. 独立したPlaywrightプログラムをPC／サーバーで実行する案。まだコード作成・ブラウザー導入・実機試験をしていない。再認証・画面変更・削除後の復旧を検証する。

現在のツールを別系統へ切り替えたら必ず動く、とは言わない。
ブラウザーを用意できてもLINEの認証維持がサーバー無人運用の未検証項目として残る。
