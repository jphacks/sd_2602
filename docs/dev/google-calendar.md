# Google Calendar読込

/accountでログイン→接続状態を確認→Googleの予定を読み込む。GOOGLE_CALENDAR_CONNECTOR_IDにBase44の利用者別Connector IDが必要。Google OAuthクライアントIDを代用しない。ブラウザへの認可トークン・生イベントの返却なし。

匿名/meと/me/pairは固定テスト専用。/accountはメインカレンダーの31日分を都度取得し、その場で演算。DB保存・相手の認可利用・LINE共有・公開は行わない。取消・重複を整理し、accepted参加または本人主催のみ評価。既存ルールのため未回答・仮承諾・辞退・透明・勤務場所は多忙扱いしない。別カレンダーは未対象。

確認順序：固定API応答テスト→lint→Base44 build→匿名RPC401→実ログイン→接続→読込。Base44プラットフォームヘッダーが必要なため、ローカル認証・利用者別接続は実機確認が必要。認証できない場合にローカルへサービス資格情報を直書きしない。

ログはrequest_id、段階、件数、所要時間、分類済みコードのみ。401認可、403 API有効化/権限、429待機、通信失敗、Connector設定を切り分ける。Base44404はID誤りと未接続を断定できない。全ページ完了前の結果は使用しない。実接続は未検証。

## 固定応答プレビュー

/me/previewで「予定あり」「予定0件」「読込失敗」を切替。GoogleのJSON形式→共通形式→既存演算→PersonalPageを通す。失敗は2ページ目で発生させ、途中結果を表示しない。匿名経路から実予定は読めない。

Base44にConnector ID設定済みでも、ローカルトークンは本番で使えない。--remoteは公開済みURLを前提とする。プレビューの実認可はホストされた実行環境・設定値・認証トークン・OAuth戻り先をそろえてから検証する。固定プレビュー成功と実認可成功を混同しない。

## Googleログインから予定読込まで

/accountを開く→未ログインなら/loginへ→「Googleでログイン」→Base44の本人セッション→「Google Calendarを接続」→Googleの閲覧許可→/accountの接続状態を確認→「Googleの予定を読み込む」。GoogleログインはBase44標準OAuth、Calendarは登録済み独自OAuthのApp user connector。別の設定・認可であり片方の成功で他方を成功扱いしない。

埋め込みプレビューのGoogleログインはSDKの公式ポップアップ処理に委ねる。Calendar認可は「別タブでGoogle接続画面を開く」から同じアプリの/accountを開いて進める。ポップアップが開かない・閉じた場合はログインボタンから再試行。Calendarからホームへ戻った場合は、同じタブに残る10分の復帰目印から/accountへ案内する。目印には時刻・固定戻り先のみでトークンは含めない。ストレージを使えない場合はホームの本人用リンクから戻る。キャンセル後も接続状態の照会結果を優先。

Base44認証設定の読取結果：Googleログイン有効、標準OAuth、SSO無効。リモート設定変更なし。Googleのアカウント選択・許可・実予定の読込は利用者が確認して実行する。
