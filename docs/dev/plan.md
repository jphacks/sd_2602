# 開発計画と合格条件

更新日：2026-10-18。現在の設計に合わせた計画。旧資料のBase44検討・PostgreSQL前提・日数配分を現行要件にしない。

## 1 前提

- Base44 CLIによるデプロイを想定。React 19・TanStack Start・JavaScriptの既存構成を維持する。
- 初版と将来機能、UIのみ・モック・実接続は[機能一覧](../spec/features.md)に従う。
- 実装前に意図・必要な図・ログとテストの計画を示して承認を得る。今回の文書更新はコード・スキーマ変更の承認ではない。
- 開発者数や残日数・担当は必要時に再確認する。過去の1日半／2日配分を現在の約束として扱わない。
- 受付と実行は分離。実行基盤はP05。UIだけの機能は業務実行へ接続しない。

## 2 実装順序

| 段階 | 作業 | 開始条件・合格条件 |
| --- | --- | --- |
| 1 | 固定入力と計算の契約を揃える | P02/P03/P04/P11の対象判断。V02〜V08の期待値と実測 |
| 2 | 仮データの本人表示、共有部分の画像保存、LINEカード生成の独立確認 | P10/P07/P13/P14。UIのみとモックを明示。V01,V09,V32〜V36 |
| 3 | 受付・キュー・実行担当・ログ | P05/P12。V12〜V14,V27〜V29 |
| 4 | Base44保存・権限・完成版切替 | V15〜V18。ログと現JSONCの差分を実装前に解消 |
| 5 | 本人・Google・LINE実接続 | P06/P07。テスト本人1人のWeb更新・画像保存後に＠リスケでカード生成。V08,V19,V22〜V24,V33 |
| 6 | 時間帯調整・候補除外・固定共有リンク | P01/P08/P09。V10,V11,V20,V21,V25,V26,V30 |
| 7 | 統合・公開・デモ | 関係する確認項目の証拠、V31、デモ時のモード表示 |

独立できる画面作業はモックで先行できるが、未決の入出力を実装済み契約としない。機能を有効化する前に対応する権限・障害時挙動を確認する。

## 3 機能単位の作業

1. 対象機能ID・判断待ちP番号・検証V番号と実装プランを提示する。
2. 既存の変更を確認し、無関係な変更を上書きしない。
3. 固定入力で正常・境界・障害を確認。必要ならモックで失敗注入する。
4. コード変更時はnpm run lintと変更に適した試験を行う。
5. PRに目的、挙動、検証証拠、未確認事項を書く。担当者間でレビューする。
6. 統合後に関係する確認リストを実行し、確認したコードの版を記録する。
7. CLI公開の対象アプリ・版を確認し、公開後も主要操作を確認する。

新しいブランチ・PR・公開は依頼された範囲で実施する。文書レビューのためにGit状態を修復・リセットしない。

## 4 確認記録・フラグ

[確認リスト](../spec/checks.md)を共通の完了条件にする。未実施を合格にしない。コードの版、環境、モード、固定入力、期待値、証拠を残す。

実行可否のフラグと、モック／実接続の切替は別に扱う。サーバー側で対象者とモードを検証する。フラグを認証・権限やデータ分離の代用にしない。

## 5 公開と移行情報

公開手順は[開発手順](README.md)を基準とし、CLIを使う。過去のBuilder公開手順・プラン情報・別リポジトリの設定を現在の接続完了と扱わない。

元のBase44アプリを保持しeject先を別アプリとした過去メモがある。表示名とbase44/config.jsoncのnameはリスケRisuke、内部識別名はrisuke。接続先DBの実状態・Secrets・外部連携は公開前に確認する。

対象スキーマのRLSは未設定として管理する。実データの投入・本番公開を文書更新と一緒に行わない。外部接続不能時のデモはモック使用を明示する。
