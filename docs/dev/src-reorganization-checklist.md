## 1. 着手前

- [ ] 作業ブランチ、基準コミット、担当、対象機能を記録する。
- [ ] git statusで既存の変更を確認し、他の作業を整理に混ぜない。
- [ ] AGENTS.mdと対象配下の追加指示を確認する。
- [ ] 最新仕様、入出力契約、実装との差を確認する。
- [ ] 実際のテストファイル・実行コマンドを確認する。npm testが存在するとは仮定しない。
- [ ] lint、対象テスト、ビルド、対象画面の変更前結果を記録する。
- [ ] 既存の失敗、接続設定不足、未実装を区別する。

## 2. 移動・削除の調査

- [ ] 旧パス、新パス、役割、呼び出し元を表にする。
- [ ] import、動的import、再export、テスト、設定、文書、スクリプトからの参照を調べる。
- [ ] URLによる利用、ファイルベースの自動探索、CSS・JSON・画像の相対パスも調べる。
- [ ] 未使用候補ごとに削除の根拠を記録する。
- [ ] 認証画面間のリンク、Base44の指定パス、仮想モジュール、生成ファイルを保護する。
- [ ] パッケージ削除は利用箇所を確認し、package.jsonとlockfileの整合を保つ。

## 3. 実装境界と挙動の維持

- [ ] routes、公開URL、認証ゲート、API受付を変更していない。
- [ ] api/base44Client.jsとViteプラグインの指定配置・順序を維持している。
- [ ] 画面から呼ぶサーバー関数の境界と、認証情報の受け渡しを維持している。
- [ ] 本人確認、所有者確認、入力検証、no-store設定を維持している。
- [ ] サーバー専用コードや秘密情報がブラウザ用生成物に混入していない。
- [ ] domainの計算がReact、Base44、通信に依存していない。
- [ ] デモと実データを区別し、データ保存・送信を新たに追加していない。
- [ ] 型の説明を追加しても、実行時の入力チェックを削除していない。

## 4. 変更後の検証

- [ ] npm run lintを実行し、変更前から増えた失敗がない。
- [ ] 調査で特定した対象テストを実行し、結果を記録する。
- [ ] LINEに触れる場合は模擬通信テストを実行し、実送信をしない。
- [ ] 開発手順に従ってビルドし、生成ファイルをコミットしない。
- [ ] 固定入力・固定時刻で日別、時間別、候補順位を変更前後で比較する。
- [ ] 該当する境界を確認する：空の予定、終日、重複、今日、除外日、候補0件、月境界、日本時間。
- [ ] 個人デモで日付選択、除外、候補表示、再読込を確認する。
- [ ] 比較機能に触れる場合、2人比較表示とPNG生成を確認する。
- [ ] 認証に触れる場合、匿名のアクセス拒否、ログイン後の復帰、ログアウトを確認する。
- [ ] Googleに触れる場合、固定応答の成功・0件・失敗を確認する。実接続は設定・許可がある環境で別途記録する。
- [ ] DBに触れる場合、ローカル・検証環境で本人データの操作と他人データへの拒否を確認する。本番を検証用に変更しない。
- [ ] verify-site.mjsを使う場合、HTTPとHTMLマーカーの確認だけであり、操作・認証確認の代替にしない。
- [ ] Docker構成に影響する場合、通常の停止・再起動で確認する。ボリューム削除を前提にしない。

## 5. レビューと完了

- [ ] git diffで意図しない挙動変更・データ変更・秘密情報がないことを確認する。
- [ ] renameを含む差分を確認し、移動と実質的な変更を説明できる。
- [ ] 古いパスの参照と、文書・テスト・スクリプトのリンク切れを確認する。
- [ ] 小さな単位でコミットし、対象外の既存変更を含めない。
- [ ] 新たな検査失敗がない。既存失敗・対象外・未検証には理由がある。
- [ ] 結果と証拠を記録し、ADRの実装状態を実態に合わせて更新する。
