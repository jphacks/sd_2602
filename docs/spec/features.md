# 機能の範囲と実行状態

更新日：2026-10-18。初版の範囲と機能状態の正本。設計対象と実装済みを区別する。

## 共通原則

- 本人の芝（日別の余裕）・時間別詳細・候補日・共有画像保存・LINEカード自動生成と固定版リンク共有を初版の対象とする。
- 計算は固定ロジック。予定名・本文を保存・公開しない。
- 計算コアはDB・API・時計を知らない。Google、LINE、DB、時計、日時変換、仮ルールは交換可能な接続口にする。
- 手動調整は日付の候補除外と時間帯編集。日別多忙度の直接編集はしない。
- 設計済み／実装済み／検証済みは別の状態。検証済みには[確認リスト](checks.md)の証拠が必要。
- 不完全な取得、古い結果、仮機能の表示を、最新の実データ処理成功として扱わない。

## 実行モード

| モード | 動作 | キュー・OperationRun | 表示 |
| --- | --- | --- | --- |
| UIのみ | 画面遷移、説明、固定プレビューのみ | 業務処理の受付・実行・保存をしない | 準備中／表示デモと明示 |
| モック | 固定入力と模擬接続で処理 | 一連の処理を検証するときだけrunを作る。fixture_checkを使用 | モックと明示。実Google・実LINEを呼ばない |
| 実接続 | 認証・入力検証後に実際の処理 | 受付と実行を分離して記録 | 受付済みと完了を分ける |

モード判定はサーバー側でも行う。UIのみの機能を別の実機能へ暗黙に振り替えない。代替画面への遷移は説明を伴い、業務処理を起動しない。将来機能のUIをすべて今作ることは決定していない。

## LINE共有の更新手順

Web側でカレンダー更新→完成版保存→共有用画像を保存。その後の＠リスケでは、保存済み同一版から候補日数分の説明付きカード＋もっと見る（同じ版の共有ページ）を生成する。LINEでの予定再取得・再計算・画像生成は行わない。画像準備失敗や古さの扱いはP13。
