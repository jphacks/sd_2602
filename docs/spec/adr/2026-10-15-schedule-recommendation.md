# ADR: 日別多忙度による予定候補の提案

- 初回決定日：2026-10-15
- 更新日：2026-10-18
- 状態：決定・提案・判断待ちと実装状況を区別する。

## 背景

日程調整の手間で誘う意欲が薄れる問題に対し、本人の余裕を見える形にし候補日を提示しやすくする。候補日は全参加者の空きや予約確定を保証しない。

## 現行の決定と理由

| 決定 | 理由 |
| --- | --- |
| 初版は本人の芝・時間別詳細・候補・共有画像保存・LINEカード自動生成と固定版リンク | 完成させる範囲を限定する |
| Base44標準User＋7種類の保存草案 | 所有者・機密性・寿命を分け、別DBを自動追加しない |
| 固定計算と候補選出を別モジュール | 計算理由と順位付けを独立して検証する |
| Google Events.listから必要項目を取得 | 終日・状態等の判断に必要。予定名・本文は保存・公開しない |
| 今日以前・除外・未取得を除き最大3件、同点は近い日 | 参考候補を水増しせず、正常0件を許容する |
| 本人連携・Google連携・利用者×グループ許可を分ける | 認証できたことを共有同意と混同しない |
| 共有は同一依頼版の固定リンク、解除・期限で停止 | 後の更新で公開内容を変えず、旧許可版を復活させない |
| 日付ボタンは投稿のみ | 投票・参加表明・確定データを作らない |
| UIのみ／モック／実接続を分ける | 見た目の完成と実処理・実接続を混同しない |
| 受付と実行を分離 | 受付完了と処理完了を分け、Web接続と独立した進行を設計する |
| 日時・調整は交換可能な仮ロジック | 試行しやすくし、入出力の意味・単位は保つ |
| 終日6時間換算・時間別は終日欄を維持 | 現実装の活動時間全体占有との差を明示し、設計を実装へ無断追従させない |
| DBは未設定項目を省略、ログはnull可 | 現スキーマの文字列定義と両立させ、境界変換を固定する |

リンクは最終候補日後・発行から最大1カ月で失効する。解除・再許可で旧リンクは復活しない。送信済みカード・テキストは残り、リンクは転送先でも閲覧され得ることを説明する。

## 将来構想

最大4人の比較、AI補正、エクスポート、詳細開発者画面、毎日の自動更新は初版で実行しない。画像保存とカード自動生成は2026-10-18の追加判断で初版の設計対象へ移した。以前の画像共有を後回しとした記述よりこの変更を優先する。

## 判断待ち

[決定と判断待ち](../decisions.md)を正本とする。特に時間帯調整の具体仮ルールと全日多忙時の扱いは今回確定せず、実行基盤・本人連携・期限境界等も選択肢と影響を記録して実装前に相談する。
