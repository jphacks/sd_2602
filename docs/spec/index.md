## 現在の設計基準

- 初版は本人の芝・時間別詳細・候補・LINE固定版リンク。画像保存と候補カード自動生成を追加。AI・比較・エクスポート・詳細開発者画面・毎日の自動更新は将来。
- 時間帯編集・日付除外を本人画面で扱う。時間帯調整の具体的な仮ルールは次の設計で相談する。
- 終日は1日6時間換算＋通常予定、活動時間上限。時間別は終日専用欄。今回のユーザー回答をdecisions.md末尾に記録。
- 純関数と外部接続を分け、日時・調整の内部実装を交換しても入出力の意味・単位を保つ。
- カレンダー更新時に共有用画像を保存する。＠リスケは保存済みの画像と候補からカードを作り、予定の再取得・画像生成は行わない。
- 受付と実行を分離する。実行基盤の選択・排他・停止復旧はP05。
- 本人表示は最新の完成版、共有表示は依頼時の固定版。計算途中の情報を公開しない。
- 権限・ログ／スキーマ対応・検証の表を実装完了条件として使う。

## 更新ルール

1. 決定／提案／判断待ちと実装済み／未検証を区別する。
2. 範囲変更は機能一覧、操作変更は外部設計へ反映する。
3. 構造変更はarchitecture.mdのクラス図、契約変更は入出力契約へ反映する。
4. 状態・保存変更はログ仕様とDB草案へ反映し、現JSONCとの差を明記する。
5. 権限と確認項目を更新し、判断理由をADRへ記録する。
6. READMEは提出用テンプレートに沿い、製品の目標と実装状態を区別する。
